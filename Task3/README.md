### Вывод о масштабируемости
Линейный рост до ~16 потоков: ускорение близко к идеальному, так как объём вычислений велик, а накладные расходы на синхронизацию минимальны.
Падение эффективности при 40 потоках: наблюдается деградация ускорения из-за:
 - Конкуренции за пропускную способность памяти (memory bandwidth saturation)
 - Накладных расходов на переключение контекста
 - Эффекта ложного разделения кэш-линий (false sharing)
Большие матрицы масштабируются лучше: при размере 40000×40000 отношение вычислений к синхронизации выше, поэтому параллелизм эффективнее.
Оптимальное число потоков: 8–16, что соответствует числу физических ядер типичного серверного процессора.
Закон Амдала подтверждается: даже при идеальном распараллеливании вычислений, последовательные участки кода (инициализация, синхронизация) ограничивают максимальное ускорение.


# Задание 2: Клиент-серверное приложение

## Ключевые особенности реализации
Шаблонный класс TaskServer<T>: универсален для любого типа результата
Синхронизация: std::mutex + std::condition_variable для безопасного доступа к очереди
Паттерн packaged_task: как в example_add_package.cpp — задача упаковывается, future сохраняется для получения результата
Безопасный get(): результат из future извлекается ровно один раз в request_result()

### Тестирование
Встроенный тест test_results():
Читает строки из файлов результатов
Парсит функцию, аргумент и ожидаемый результат
Повторно вычисляет значение эталонной функцией
Сравнивает с погрешностью 1e-4
