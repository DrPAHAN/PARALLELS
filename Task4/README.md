# Лабораторная работа №4

## Цель работы
Реализовать систему параллельного опроса датчиков с использованием потоков (threading), организовать обмен данными через потокобезопасные очереди (queue) и обеспечить корректное освобождение ресурсов по идиоме RAII.

## Задачи
- Чтение данных с USB-камеры (через OpenCV) и виртуальных датчиков SensorX
- Обработка каждого датчика в отдельном потоке
- Передача данных между потоками через очереди с политикой «только последние значения»
- Отображение видеопотока с наложением показаний датчиков
- Безопасное завершение программы по нажатию клавиши q

## Зависимости
```
pip install opencv-python numpy
```
Все остальные модули (argparse, threading, queue, logging, os, sys, time) входят в стандартную библиотеку Python.

## Управление
- Завершение программы: q (в активном окне OpenCV)
- Аварийное завершение: Ctrl+C в терминале

После нажатия q программа корректно завершает все потоки, освобождает ресурсы камеры и окна, и записывает финальные сообщения в лог-файл.

## Архитектура решения
### Классы датчиков
```
Sensor (абстрактный базовый класс)
├── get() → абстрактный метод получения данных
│
├── SensorX (виртуальный датчик)
│   ├── __init__(delay: float)
│   └── get() → int: имитирует работу с задержкой, возвращает счётчик
│
└── SensorCam (USB-камера через OpenCV)
    ├── __init__(camera_id, resolution)
    ├── get() → np.ndarray: чтение кадра
    └── __del__(): RAII — освобождение ресурса камеры
```

### Класс отображения (RAII)
```
WindowImage
├── __init__(display_freq): создание окна, расчёт waitKey
├── show(img) → int: отрисовка + обработка событий + возврат клавиши
└── __del__(): RAII — закрытие окна через cv2.destroyWindow()
```

### Многопоточная модель
```
Главный поток (main)
│
├─► Поток 1: sensor_worker(SensorCam) → queue[0]
├─► Поток 2: sensor_worker(SensorX@0.01s) → queue[1]  # ~100 Гц
├─► Поток 3: sensor_worker(SensorX@0.1s)  → queue[2]  # ~10 Гц
├─► Поток 4: sensor_worker(SensorX@1.0s)  → queue[3]  # ~1 Гц
│
└─► Цикл отображения:
    ├─► Опрос всех очередей (неблокирующий get_nowait)
    ├─► Кэширование последних значений (при отсутствии новых — старые)
    ├─► Формирование кадра: видеопоток + панель датчиков (правый нижний угол)
    └─► Отрисовка через WindowImage.show()
```

### Очереди и синхронизация
- Используется queue.Queue(maxsize=1) для каждого датчика.
- Политика: только самые свежие данные. Если очередь полна, старое значение удаляется перед записью нового.
- Синхронизация завершения: threading.Event (stop_event) — потоки проверяют флаг на каждой итерации.

### Логирование
- Все события пишутся в log/lab.log и дублируются в консоль.
- Уровни: INFO (штатная работа), WARNING (потеря кадра), ERROR (критические сбои).
- При ошибках инициализации (камера не найдена, неверное разрешение) программа завершается с кодом 1.

## Точность тайминга на разных ОС
```
Датчик   | Задержка | Ожидаемая частота | Реальная частота (macOS) | Погрешность
---------|----------|-------------------|--------------------------|-------------
SensorX0 | 0.01 с   | 100 Гц            | ~85–90 Гц                | ~10–15%
SensorX1 | 0.1 с    | 10 Гц             | ~9.7–10 Гц               | ~2–3%
SensorX2 | 1.0 с    | 1 Гц              | ~0.98–1.0 Гц             | <2%
```
### Причины:
- Минимальная гранулярность time.sleep() на macOS: ~10–15 мс.
- Накладные расходы на переключение контекста, работу GIL, операции с очередями.
- Приоритизация потоков: ОС может отдавать приоритет главному (GUI) потоку.

### Вывод
Реализована многопоточная система опроса датчиков с использованием идиомы RAII, очередей для обмена данными и неблокирующего чтения. Наблюдаемая погрешность высокочастотного датчика обусловлена ограничениями time.sleep() и GIL в Python, что допустимо для демонстрации принципов параллелизма в учебных целях.
