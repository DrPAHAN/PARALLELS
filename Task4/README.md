# Лабораторная работа №4

## Описание
Многопоточная система сбора данных с нескольких датчиков и USB-камеры. Реализована по паттерну **Producer-Consumer**: каждый датчик работает в отдельном потоке, передаёт данные в очередь, а основной поток неблокирующе забирает последние значения, формирует изображение с OSD-оверлеем и выводит его в окно.

## Архитектура решения
| Компонент | Роль | Ключевые механизмы |
|:---|:---|:---|
| `Sensor` | Абстрактный базовый класс | Требует реализации `get()` |
| `SensorX` | Симуляция датчика с задержкой | Отдельный поток → `time.sleep()` → `queue.Queue` |
| `SensorCam` | Чтение кадров с камеры | `cv2.VideoCapture` → поток → очередь → fallback `AVFoundation/V4L2` |
| `WindowImage` | Управление окном вывода | `cv2.imshow` + `cv2.waitKey` → обработка `q` |
| `main()` | Основной поток | `get_latest()` из очередей → отрисовка → цикл `while` |

## Запуск программы
```
# Значения по умолчанию (камера 0, 1280x720, 30 FPS)
python3 task4.py

# С явными параметрами
python3 task4.py --camera 0 --resolution 1280x720 --fps 25
```

## Параметры командной строки (argparse)

| Флаг | Тип | По умолчанию | Описание |
|------|-----|--------------|----------|
| --camera | str | 0 | Индекс камеры (на macOS используйте 0, 1...) |
| --resolution | str | 1280x720 | Желаемое разрешение камеры в формате WxH |
| --fps | float | 30.0 | Частота обновления окна отображения (Гц) |

## Соответствие требованиям задания
| Требование | Реализация |
| ---------- | ---------- |
| Идиома RAII | Все ресурсы захватываются в __init__, освобождаются в close() и __del__. При исключении в конструкторе ресурсы корректно подчищаются до raise.|
| Постоянное чтение датчиков | Каждый датчик запускает фоновый threading.Thread, который в цикле опрашивает устройство и кладёт данные в queue.Queue. |
| Обмен через очереди | Используется queue.Queue. Главный поток вызывает get_nowait() для получения самого свежего значения без блокировки. |
| Наследование от Sensor | SensorX и SensorCam реализуют абстрактный метод get(). |
| Класс WindowImage | Управляет окном, задаёт частоту отображения, корректно закрывает окно в деструкторе. |
| Парсинг CLI | Модуль argparse: камера, разрешение, FPS. |
| Безопасный выход | Нажатие q или Ctrl+C → блок finally → вызов close() у всех объектов → логирование. |
| Логирование | Модуль logging, файлы сохраняются в папку log/. Критические ошибки выводятся в stderr. |
| Вывод данных на кадр | Данные датчиков отрисовываются в правом нижнем углу в белой рамке чёрным шрифтом. Размер рамки адаптируется под длину текста. |
