# Лабораторная работа №5: Ускорение инференса YOLOv8s-Pose на CPU

## Описание
Реализация параллельной обработки видеопотока для детекции поз (Pose Estimation) с использованием модели `yolov8s-pose`. 
Основная цель: измерить и ускорить время инференса на CPU за счёт распараллеливания обработки кадров между процессами, соблюдая идиому RAII для корректного управления ресурсами OpenCV.

## Установка зависимостей
```
pip install ultralytics opencv-python numpy
```

Модель yolov8s-pose.pt загрузится автоматически при первом запуске

## Запуск
### Однопоточный режим
```
python3 task5.py --video input.mp4 --mode single --output out_single.mp4
```
### Многопоточный режим
```
python task5.py --video input.mp4 --mode multi --output out_multi.mp4
```

## Параметры argparse

| Аргумент | Тип | Описание |
| -------- | ---- | ------- |
| --video | str | Путь к входному видео (рекомендуется 640×480) |
| --mode | str | single (1 поток) или multi (пул процессов) |
| --output | str | Путь к выходному видеофайлу с наложенными KeyPoints |
| --workers | int | Число дочерних процессов (по умолч. = cpu_count()) |
| --model | str | Путь к .pt файлу модели (по умолч. yolov8s-pose.pt) |

## Архитектура и реализация
### 1. Идиома RAII
Класс VideoResource инкапсурует управление cv2.VideoCapture и cv2.VideoWriter:
Конструктор (__init__): открывает видео, определяет реальные FPS/разрешение, подбирает рабочий кодек (avc1/mp4v/XVID) под ОС.
Деструктор (__del__): гарантирует вызов .release() при уничтожении объекта, предотвращая битые выходные файлы.
Безопасность: дополнен try/finally в функциях обработки для гарантированного сброса буфера на диск даже при исключениях.

### 2. Выбор параллелизма: Процессы vs Потоки
Инференс нейросети является CPU-bound задачей. В Python глобальная блокировка интерпретатора (GIL) не позволяет потокам (threading) выполняться параллельно на нескольких ядрах.
Поэтому используется concurrent.futures.ProcessPoolExecutor, создающий отдельные процессы ОС. Каждый процесс получает собственную копию модели через initializer=init_worker, что соответствует рекомендациям YOLO Thread Safe Inference.

### 3. Сохранение порядка кадров
Процессы возвращают результаты асинхронно. Для корректной сборки видео используется массив processed = [None] * total_frames, куда каждый результат кладётся по индексу исходного кадра: processed[idx] = res_frame.


## Результаты тестирования

| Режим | Кадров | Время выполнения | Средняя скорость | Ускорение |
| ----- | ------ | ---------------- | ---------------- | --------- |
| single | 227 | 95.2895 сек | 2.38 FPS | 1.00× | 
| multi | 227 | 71.6454 сек | 3.17 FPS | ~1.33× |

## Вывод
- Достигнуто ускорение ~33% за счёт распараллеливания.
- Линейного ускорения нет из-за накладных расходов на межпроцессное взаимодействие (IPC), сериализацию кадров через Future, а также ограничений пропускной способности памяти и теплотроттлинга CPU.
- Оптимальное число процессов подбирается экспериментально: увеличение свыше числа физических ядер приводит к конкуренции за ресурсы и падению FPS.
